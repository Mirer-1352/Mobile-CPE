# 真机验收记录

当前状态：0.9.0 已完成一台 OnePlus 8T 的部分实测和重构回归，见 [DEVICE_RESULTS.md](DEVICE_RESULTS.md)。下表是完整验收清单，不能将未测项目视为通过。继续测试时请记录机型、ROM、Android API、Root 方案、LSPosed 版本及诊断错误。

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| Android 9/10 | 授权 Root，开 Wi-Fi 与 USB | 成功收到回调并出现实际接口；以太网仍可保存期望，提示执行不支持 |
| Android 11+ | 接 OTG 网卡并开以太网共享 | 下游电脑拿到 DHCP 地址并可访问网络 |
| USB 重插 | 启用守护和 USB，拔线再插 | 显示等待接线，插线后重开；下游可访问网络 |
| 网卡重插 | 以太网运行中拔插网卡 | 退避重试，接口恢复后下游重新拿到地址 |
| 系统关闭 | 在系统设置关闭已选共享 | 自动恢复开启时重开；关闭时不持续重试 |
| 显式关闭 | 关闭应用内某共享开关 | 实际接口消失，重启不重新开该共享 |
| 开机 | 启用开机恢复，重启且暂不解锁 | Root 允许时锁屏阶段恢复服务；解锁后无重复循环 |
| 息屏 | 息屏 30 分钟并拔插线 | 前台服务存活，重新接入恢复 |
| 权限拒绝 | 拒绝 Root 和电话权限 | 明确提示，不显示虚构 5G / 速率 / 客户端数量 |
| Root 撤销 | 运行中撤销 Root 并结束 Root 子进程 | 通道错误，实际状态标为未确认，之后可重新授权 |
| 设备数量 | Wi-Fi 连接 0、1、2 台，再断开一台 | 数量对应 SoftApCallback，不以 ARP 残留计数 |
| 双 SIM | 切换默认数据卡 | 显示新的数据卡运营商与信号，不沿用旧卡值 |
| 4G / 5G | SA/NSA/LTE 环境切换 | 系统报告一致；未知时不猜测 |
| 流量 | 下游下载再上传并重开共享 | 方向正确；接口重置没有负数和尖峰；记录卸载偏差 |
| 默认桌面 | 设默认，按 Home 和重启 | 回到面板，可从面板打开系统设置 |
| LSPosed 102 | 框架启用模块后打开应用 | 显示框架 API，缺少 system 时自动申请；仅 android 不视为已授权 |
| 作用域批准 | 在管理器批准申请后返回 | 重新读取实际作用域并提示重启，不将授权当作 Hook 已注入 |
| 作用域拒绝 | 拒绝申请并多次切回应用 | 不反复弹窗；手动申请可重试 |
| 作用域撤销 | 已授权后在管理器移除 system，再返回应用 | 同步撤销状态并重新申请 |
| 服务重连 | 框架服务断开并恢复 | 清除旧状态，重新获取实际作用域；后台不弹申请 |
| 旧框架 | 仅支持旧版 Xposed API 的设备 | 提示需要 API 102，Root 共享功能仍可使用 |
| LSPosed | system 作用域授权并重启，开接管 | 按 Home 回到面板；不支持入口时系统仍可正常用 |
| LSPosed 恢复 | 关接管 / 停模块 / 卸载 APP | 原桌面可用，系统无启动循环 |
| 窄屏和大字 | 字体 200%、横竖屏 | 可滚动访问全部开关，关键按钮可点击 |
| Root 更新前台 | 合法高版本缓存/下载后不确认安装 | 自动覆盖、独立执行器存活、面板按原前台状态恢复 |
| Root 更新后台 | 原桌面前台，boot=false，只启动守护服务 | 自动更新与恢复共享，不拉起 CPE 界面 |
| 更新失败 | 错哈希、错签名、非升级、Root 拒绝、低于 minSdk | 拒绝安装，原应用保留，诊断记录，延后重试 |
| 更新后禁用守护 | 更新前 enabled=false | 包替换不重新启用共享 |
| 多用户 | 在次要用户中更新 | 按发起用户恢复；系统同包 APK 全局更新语义不变 |
| 期望持久化 | USB/以太网保持开启，多次结束进程重开、旋转、进设置 | 开关始终为保存的期望；未实际共享的图标保持白色 |
| 条件恢复 | 保持期望开启，拔插 USB、接网卡/插网线 | 不改期望；连接变化后清除旧退避并重新尝试 |

0.7.3 已实测 Root 前台/后台安装与失败拒绝，其他系统/硬件的适配审查及证据边界见 [COMPATIBILITY.md](COMPATIBILITY.md)。
# 0.8.0 框架守护追加验收

启用支持 API102 的框架与手机CPE 模块，批准 system 作用域并重启后执行。0.8.0 时本机框架禁用；0.8.2 经用户授权已完成该机实际注入、强停、冻结与暂停验证，其他设备仍需分别验收。不要用独立 Root app_process 代替真实 system_server。

- 设置确认实际框架心跳已连接，然后杀死或 force-stop 手机CPE：服务应从外部恢复，面板不抢当前前台；三个期望开关保持原值。
- 关闭总守护，再结束应用：等待至少一分钟不应拉起；重新打开主动开启后恢复。单独关闭系统框架守护也不得拉起。
- boot=false 后重启不启动；手动启动后本轮仍能守护。boot=true 时重启到未解锁阶段也检查共享服务。
- 连续崩溃不得超过每五分钟三次恢复；恢复稳定后正常继续守护。升级中不与安装器争抢，安装完成后恢复；卸载/清除数据清除旧策略。
- 另测 Android 9、不同 ROM、其他 Root 方案、次用户和用户停止/启动；日志不得出现由模块异常引起的 system_server 崩溃。
- 强停/冻结验收保持普通系统设置页在前台，核对 system UID/PID 与 lastRecovery 的动作、时间、成功状态及新进程心跳。默认 HOME 重开、普通 ANR 重启或仅 PID 改变均不能单独计作守护成功。暂停时要求无共享前台服务、无新的恢复动作；HOME/模块 Binder 产生的空应用进程单独记录。

# 0.8.1 常亮与防烧屏追加验收

- 长按仪表进入 MCPE → 屏幕，开关屏幕常亮；检查自身窗口 KEEP_SCREEN_ON 标志随开关添加/撤销，不修改全局 screen_off_timeout。
- 防烧屏默认开启。回到面板，记录三个状态图标边界，真实等待 180 秒及动画完成；三图标应具有相同的非零 X/Y 偏移，各轴不超过 ±16 物理像素，并为 4 的倍数，原尺寸不变。
- 切回原桌面，再进入面板，位移复位并重新计时；关闭防烧屏后回到原位置。确认横竖屏边缘无裁切、开关仍能按移动后的位置操作。
- 测试前后核对 Wi-Fi/USB/以太网、总守护、boot、recover、VPN 原选择一致，只恢复本次修改的屏幕选项，不恢复整份旧 router.xml。
